# W10-A evidence — Dutch mapping event

- Packet: `W10-A`
- Agent: `OPENCODE-DS41F`
- Date: 2026-10-31

## RED observed

The Dutch contract set published `iam.identity.verified.v1` and `ums.member.mapping.changed.v1`, whose payload
carried `identityId` (a global IAM identity) — both forbidden by the accepted design. The new schema rejects
that shape (see the `forbidden-identity` fixture).

## GREEN

- `contracts/events/dutch/json-schema/dutch.member-profile.mapping-changed.v1.schema.json` — closed envelope
  with `producer=dutch-ums`, `eventType` const, `aggregate.type=MEMBER_PROFILE`, and the exact six-field payload
  `appRegistrationId, appSubject, memberId, mappingVersion, profileState, lifecycleState`.
- `contracts/imported/iam/event-envelope.schema.json` — copy of the pinned IAM envelope (immutable input).
- `contracts/events/asyncapi.yaml` — publishes only the new mapping channel; legacy identity and mapping channels
  and schemas removed.
- Verified by the W10-C harness: `npm test` 8/8, `npm run validate` exit 0; the forbidden fixture fails with an
  `additional properties` error.

## Acceptance mapping

| Criterion | Evidence |
|---|---|
| Exact six-field payload | schema `payload.required`/`additionalProperties:false`; valid fixture |
| IAM envelope shapes (`evt_`, `cor_`, aggregate, destination) | schema patterns and cross-field checks |
| No global identity | forbidden fixture rejected |
| Legacy channels unpublished | asyncapi contains one channel; directories removed |

## Risks
