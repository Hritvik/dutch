## Correlation

- The filter accepts any value matching the contract pattern `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`,
  regenerates otherwise, and echoes on success and rejection paths.
- It runs at `HIGHEST_PRECEDENCE`, so a security rejection still carries the value; the gateway
  re-sets its own value after copying upstream headers, so the client sees one identity.
- Verified by test and by reading `GatewayRoutingFilter` (it streams the upstream body verbatim).

## Privacy

- Ready body exposes only `memberId`, `displayName`, `profileState`, `lifecycleState`.
- No app subject, `aps_` reference, global identity, token, credential, password or email, on the
  ready, 409 and state bodies; tests assert absence case-insensitively.
- The subject is used for lookup and never returned.

## Findings

No critical or high finding. Two low findings and three informational notes.

- **F1 (low) — header casing.** The contract and the gateway constant are `X-Correlation-ID`; UMS
  emits `X-Correlation-Id`. HTTP names are case-insensitive so no client breaks, but the service is
  literally inconsistent with its own contract and with `CorrelationId.HEADER`. One-line fix in
  `CorrelationIdFilter`.
- **F2 (low) — envelope fallback.** `UmsSecurityConfiguration.envelope` falls back to
  `correlationId: ""`, which violates the contract pattern, while `ProfileErrorHandler` uses
  `cor_unknown`. Unreachable in the current wiring (the correlation filter precedes the security
  chain) but two fallbacks for one fault, one of them contract-invalid.
- **F3 (low) — skipped suite is silent.** Without `DOCKER_HOST`, `:services:ums:test` reports BUILD
  SUCCESSFUL while skipping 16 of 34 tests, including every integration test. `@Testcontainers(
  disabledWithoutDocker = true)` is the cause. The evidence claims are reproducible — I reproduced
  34/34 — but the packet's verification command alone gives a false green. Recommend documenting the
  environment in the packet or failing instead of skipping in CI.
- **F4 (info) — unmapped runtime faults bypass the envelope.** The advice catches
  `IllegalArgumentException` only, so a `DataAccessException` (database down) returns Spring Boot's
  default error body, which the gateway forwards verbatim. Ledger and notification use the same
  scoped-advice pattern, so this is portfolio-wide hardening, not a W-12 regression.
- **F5 (info) — unreachable enum members.** `ProfileReadyResponse.lifecycleState` advertises
  `SUSPENDED` and `DEPARTED`, but `/me` returns 200 only for `ACTIVE`; the other values are
  unreachable in a ready body.
- **F6 (info) — stale name.** `ProfileErrorHandler.invalidRequest` now emits `internal_error` (500),
  not `invalid_request`.

## Verdict

Approved. Acceptance asks for no critical, high or medium finding; F1–F3 are low and none blocks the
surface. F3 is the one to fix next: a verification step that can pass without running the journey
test is how a green board becomes untrue.
