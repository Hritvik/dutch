## Implemented

- **Ledger outbox** (`V12`, `com.dutch.ledger.outbox`): the committed envelope carries
  schema version, producer, correlation/causation IDs, claim metadata, attempts, and
  last error. Expense and Settlement commands write `ledger.expense.committed.v1` /
  `ledger.settlement.committed.v1` in the financial transaction.
- **Relay** (`OutboxRelay`): claims with `FOR UPDATE SKIP LOCKED`, publishes outside the
  claim transaction, marks `published_at`, and retries with exponential backoff
  (`next_attempt_at`, capped at one hour). After five failures the event is dead-lettered
  and stays unpublished so publish-lag alerts still see it; the claim excludes
  dead-lettered rows. The HTTP transport has connect/read timeouts and the scheduler
  runs a small pool.
- **Notification service**: device registration/list/removal, push preferences, caller
  privacy deletion, `/internal/events` consumer with `X-Service-Token`, `inbox_event`
  dedupe by event id, per-recipient preference checks, per-device deliveries, and a
  pluggable push sender (development logging; provider adapter later). Push runs after
  the delivery transaction, so a failed push never affects finance.
- **Gateway**: routes `/api/v1/notifications`, `/api/v1/reports`, and
  `/api/v1/privacy` to their owners, and registers a fixed-window per-IP rate limit
  before the security chain (429 with `Retry-After`); expired windows are pruned.
  Authenticated route tests prove those paths reach routing instead of denial.
- **Privacy fan-out**: consuming `ums.member.anonymized.v1` or
  `iam.identity.deleted.v1` deletes the member's notification deliveries, devices, and
  preferences, records the inbox dedupe row, and creates no push; replay is a no-op.
- **Privacy export**: `GET /api/v1/privacy/export` returns only the caller's authorized
  Group, Direct Expense, and Series projections. Direct Expenses use a dedicated
  view without `entries` or `streamIds`, enforced by the contract and a nested
  absence test. The notification privacy endpoint deletes device,
  preference, and delivery data.
- **Safety reports** (`V13`, `POST /api/v1/reports`): category, scope, and bounded
  details; the receipt echoes only the report id and RECEIVED status.
- **Contracts**: notification OpenAPI and validated device fixture; ledger
  expense/settlement event JSON Schemas, fixtures, AsyncAPI channels, and invariant
  tests (aggregate id must match the payload).
- **Runbook**: `docs/operations/runbooks/outbox-notifications.md` covers stuck outbox
  rows, dead-letter replay, notification consumer failures, privacy deletion, rate
  limits, and recovery rules.

- **Mobile notification entry point** (`apps/mobile/app/notifications.tsx`): registers a
  development device, shows push preferences and active devices, and deletes
  notification-owned data. Push is presented as a refresh prompt; Activity remains
  authoritative.

## Incident rehearsal (test environment)

The outbox integration test performs the runbook's dead-letter recovery: a failing
transport produces five attempts and a dead-letter row; the row is removed, the event
is reset (`published_at/claimed_at = NULL`, attempts `0`), and a healthy relay
publishes it exactly once. This is a test-environment rehearsal, not a production
incident exercise.
