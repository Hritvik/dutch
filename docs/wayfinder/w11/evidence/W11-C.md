## Fault matrix

| Scenario | Observed |
|---|---|
| Two threads deliver the same event concurrently | one profile, one outbox, one inbox; same member id |
| Restart with a new consumer instance | same mapping, no second effect |
| Same event id with a different payload | `ConflictingOnboardingEventException`, no second effect |
| Outbox CHECK failure through the Spring proxy | inbox, profile and outbox all rolled back |
| Conflicting reuse of an event id | durable `inbox_quarantine` row (`PAYLOAD_CONFLICT`), no second effect |
| Emitted event | validates against the pinned Dutch JSON schema from the outbox row |
| UMS role vs IAM database | connection to `dutch_iam` is denied |

## Risks

- The rollback test fails at the outbox insert, so the checkpoint rollback assertion is vacuous.
- `dutch.environment` defaults to `development`; deployment must set it.
- Payload assertions are containment-based, not an exact key-set check.
