# S2 evidence — Groups and membership

Status: all S2 acceptance paths implemented and the service boots against PostgreSQL; independent re-review pending
Agent: opencode/dutch-agent
Date: 2026-11-01

## Implemented

- **Domain** (`services/ledger/src/main/java/com/dutch/ledger/group`): `Group`,
  `Membership`, roles and states with the settled invariants — at least one ACTIVE
  Admin, INVITED/PLACEHOLDER without app access, INACTIVE read-only history, a removed
  member requiring a fresh invitation and acceptance before reactivation (also
  enforced on replay), and no membership changes to an archived group.
- **Schema**: `V3__create_group_membership.sql` adds `member_group`,
  `group_membership`, and `group_membership_event`, with checks and deferred
  constraint triggers enforcing the active-Admin rule at commit.
  `V4__app_subject_member_mapping.sql` adds the app-subject authorization projection.
- **Persistence and concurrency**: `JdbcGroupRepository` and `JdbcMemberResolver` are
  real service beans; `GroupRepository.save` updates only when the stored
  `aggregate_version` still matches. Mutations require `If-Match: "<version>"`; a
  mismatch is 409 `stale_version`, a malformed or missing header is 400
  `invalid_request`.
- **Membership replay**: `JdbcGroupMembershipEventConsumer` persists each event once,
  rejects a skipped version, applies it through the aggregate, and saves with the
  previous version. The unique `(group_id, aggregate_version)` row makes replay
  restart-safe. `LedgerApplicationDatabaseTest` boots the service with Flyway and
  asserts the consumer is instantiated.
- **Mapping feed**: `JdbcMemberMappingConsumer` applies the UMS mapping fact
  idempotently, classifies an event-id reuse race as a conflict, ignores stale mapping
  versions, and gates resolution on `ACTIVE`.
- **HTTP**: `/api/v1/groups` create/list, group read, membership invite/placeholder,
  activate, deactivate, role change, archive, and reopen, all authenticated with the
  OAuth2 resource server. Errors use `invalid_request`, `unauthorized`, `forbidden`,
  `not_found`, `stale_version`, `last_admin`, `conflict`, and `service_unavailable`
  with a correlation id. A non-member gets 404 on every group scope, including
  self-activation and before the version check; a readable non-admin gets 403.
- **Contract**: `contracts/http/ledger/openapi.yaml` and fixtures wired into the
  validation harness, including the required `If-Match` header, the `stale_version`
  and `last_admin` codes, a negative unknown-role case, and a bearer-auth check on
  every route.
- **Gateway**: `/api/v1/groups/**` requires authentication and forwards to the Ledger.
- **Mobile**: closed `groups-client` parsing; group list, create, and detail screens;
  invite, activate, deactivate, role change, archive, and reopen actions; loading,
  empty, retry, stale-version, and last-admin states. Admin controls are hidden for a
  non-admin or archived group.

so they prove the client contract and conditional rendering, not the live Ledger.

## Residual findings

- The controller tests use in-memory repository/resolver adapters; the real JDBC
  wiring is covered by `LedgerApplicationDatabaseTest` and the repository/mapping/replay
  integration tests rather than an HTTP integration test.
- The mock API has no authorization or 409 path, so the device flows prove conditional
  rendering rather than API denial; the API denial is covered by `GroupControllerTest`.
- A concurrent membership edit returns `stale_version`; the mobile refreshes and tells
  the person, but there is no merge/retry composer for the stale command.
- The legacy UUID mapping types are deprecated but retained for the transition.
