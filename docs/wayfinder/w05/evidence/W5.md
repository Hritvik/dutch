Status: implementation green, device acceptance pending

## Implemented

- **Gateway routing** (`services/gateway`): a thin `GatewayRoutingFilter` forwards
  `/api/v1/me`, `/api/v1/me/**`, and `/api/v1/ledger/**` to the configured UMS and
  Ledger base URLs, preserves method, query, headers and body, echoes or regenerates
  `X-Correlation-Id`, and returns the published error envelope when the upstream is
  unavailable. The security chain now requires authentication on both surfaces;
  everything else stays denied.
- **Route configuration** (`application.yaml`): `GATEWAY_UMS_BASE_URL` and
  `GATEWAY_LEDGER_BASE_URL` with local defaults.
- **Mobile contract client** (`apps/mobile/src/profile-client.ts`): closed parsing of
  `/api/v1/me/profile-state` and `/api/v1/me`, a positive-integer retry hint, bearer
  auth, and 409-as-profile-required handling.
- **Mobile shell** (`apps/mobile/app/index.tsx` plus `app-screen.ts`, `app-config.ts`,
  `token.ts`): boot from SecureStore, sign in with S256 PKCE, keep the profile-required
  screen until the authoritative state is ready, retry on the bounded hint, show an
  honest offline state, and reach the authenticated shell only after `/me` returns a
  Member. Ledger availability is derived from the session reducer, never from the
  profile-state response alone.
- **Tests**: gateway routing/authentication (7), mobile (26 across contract parsing,
  gate, config, token, OAuth, session).

## Residual findings

- The router blocks a servlet thread per request; acceptable for the MVP, revisit if
  gateway latency or concurrency becomes a constraint.
- Correlation is pass-through with UUID generation; the pinned `cor_` vocabulary lands
  with `dutch-ref/W12-B` (UMS agent).
- No rate limit is applied yet; that belongs to the security slice.
