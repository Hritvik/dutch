# W11-A evidence — app-scoped UMS schema

- Packet: `W11-A`
- Agent: `OPENCODE-DS41F`
- Date: 2026-10-31

## RED observed

The prototype schema keyed `member_profile` and `inbox_event` by UUID identity/event ids and had no
app registration or App Subject columns, so an onboarding-ready event could not be stored without a
global identity. `V3` replaces those tables.

## GREEN

`./gradlew :services:ums:test` (JDK 21, Testcontainers PostgreSQL 16) — BUILD SUCCESSFUL; migration
tests pass.

## What was built

- `V3__app_scoped_member_profile.sql`: forward-only replacement of the prototype tables.
  - `member_profile`: `mem_` text id, `(app_registration_id, app_subject)` unique, closed
    `profile_state`/`lifecycle_state` vocabularies, `mapping_version`.
  - `inbox_event`: keyed `(producer, event_id)`, stores a 64-hex payload fingerprint.
  - `inbox_checkpoint`, and an `outbox_event` with text `evt_` ids and IAM envelope columns.
- `MemberProfile`, `ProfileState`, `MemberLifecycleState` (ACTIVE/SUSPENDED/DEPARTED),
  `MemberProfileRepository`/`JdbcMemberProfileRepository` (lookup by app + subject).

## Review 01 remediation

- **Destructive upgrade decision recorded**: V3 intentionally discards the prototype tables (no live UMS
  population). `MigrationIntegrationTest.upgradesAV2DatabaseByDiscardingTheLegacyPrototypeTables` seeds a V2
  database, migrates to V3, asserts the legacy row/column are gone and the app-scoped columns exist.
- Outbox columns now carry literal CHECKs (event type, producer, aggregate type/id, correlation/causation,
  destination).
- Remaining low: the unused `IdentityVerifiedEvent` record.

## Risks

- V3 is destructive by recorded decision; it must not run against a database with real member data.
