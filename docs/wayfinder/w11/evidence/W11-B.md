# W11-B evidence — idempotent onboarding consumer

- Packet: `W11-B`
- Agent: `OPENCODE-DS41F`
- Date: 2026-10-31

## RED observed

The legacy consumer only understood `iam.identity.verified.v1` with a UUID identity and emitted
`ums.member.mapping.changed.v1` carrying `identityId`; it could not consume the pinned onboarding
event or emit the pinned Dutch mapping payload.

## GREEN

`JdbcMemberProfileConsumerIntegrationTest` — 3/3 against PostgreSQL 16 (duplicate delivery, distinct
event for one subject, pinned envelope/payload, conflicting event id fails closed).

## What was built

- `OnboardingReadyEvent` with closed validation of the IAM event id, app, subject, activation and
  onboarding fields.
- `JdbcMemberProfileConsumer.consume` in one transaction: inbox insert with canonical fingerprint;
  duplicate same-payload delivery is a no-op; a different event id for the same subject returns the
  existing mapping; conflicting reuse of an event id fails closed; one profile, one outbox event and
  a checkpoint advance per logical onboarding.
- Emitted outbox event: `dutch.member-profile.mapping-changed.v1`, producer `dutch-ums`, aggregate
  `MEMBER_PROFILE`, destination app, correlation/causation from IAM, payload exactly
  `appRegistrationId, appSubject, memberId, mappingVersion, profileState, lifecycleState`.
- Profile starts `PROFILE_REQUIRED` / `ACTIVE`; the mapping event mirrors that honestly.
- `MemberProfileService` (prototype in-memory duplicate) removed.

## Acceptance mapping

| Criterion | Evidence |
|---|---|
| Duplicate delivery no-op | integration duplicate test |
| Different event id, same subject → existing mapping | integration replay test |
| Same event id, different payload fails closed | conflict test |
| One inbox/profile/outbox per onboarding | counts asserted |
| Allowlisted PII-free payload | payload assertions |
| No IAM persistence access | own datasource only |

## Review 01 remediation

- **High fixed**: `causationId` is nullable, matching the IAM producer (`V11` writes `null`) and the pinned
  envelope; all tests now use the canonical null value.
- **Medium fixed**: the input model and fingerprint now include `activationState` and `requiredProfileState`,
  so a same-event-id replay that changes either fails closed.
- **Medium addressed**: the `@Transactional` boundary is proven in `OnboardingTransactionIntegrationTest`
  (W11-C): an outbox CHECK failure rolls back inbox, profile, outbox and checkpoint.
- Acceptance wording corrected (one inbox row per event identity; one profile/outbox per subject).
