## Delivered

- `CorrelationIdFilter` accepts an inbound value matching `^cor_[A-Za-z0-9]{16,124}$`,
  generates `cor_` plus a random token otherwise, and echoes the result on every response.
  It runs at highest precedence, so a security rejection still carries the correlation.
- `UmsSecurityConfiguration` writes the pinned envelope for 401 (`unauthorized`) and 403
  (`forbidden`) from both the resource-server and exception-handling paths.
- `ProfileErrorHandler` maps a controller failure to `invalid_request` / `Request is invalid`;
  the ad-hoc `invalid_identity_subject` code is removed.

## Verification

`./gradlew :services:ums:test` passes. Tests assert the pinned correlation echo and
regeneration, the unauthorized envelope body and correlation, the invalid-request envelope,
and that responses still expose no identity or subject.

## Limits

- Only the codes the adapter can currently emit are covered; `rate_limited`, `not_found`,
  `internal_error`, and `service_unavailable` are defined by the contract but have no
  producer in this slice.
- The contract OpenAPI lives at `contracts/http/gateway/openapi.yaml`; schema validation of
  the envelope is exercised by the W-10/W-12 harness rather than this service's tests.

## Review 01 remediation

- **Correlation accepted only `cor_…`.** The contract's own parameter pattern is
  `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`, and the sibling ledger filter echoes any conforming
  value. UMS now does the same and only regenerates a non-conforming or over-long value, so
  gateway/ledger/UMS logs keep one identity.
- **A corrupt profile row was reported as `400 invalid_request`.** It is an internal fault, so
  the advice now answers `500 internal_error`; the envelope and correlation are unchanged.
- Null correlation is normalized rather than throwing, and tests cover the non-`cor_` echo,
  over-long regeneration, and the internal-error envelope.
