## Implemented

- **Release provenance** (`tools/release-record.mjs`): builds and validates the
  schema-v1 record (artifact digest, source revision, built-at, workflow run URL).
  `infrastructure/provenance/release-record.example.json` validates, and the quality
  workflow validates it on every run.
- **Restore rehearsal**: `infrastructure/local/bin/rehearse-restore.sh` dumps every
  service database, restores into a sibling database, checks Flyway history and
  failures, compares Ledger entry/outbox counts, and reconciles
  `member_balance_projection` against `obligation_entry`. The same procedure is
  executed in `RestoreRehearsalIntegrationTest`: a migrated, populated Ledger is
  dumped with `pg_dump`, restored into a new database, and reconciled (entries,
  outbox, Flyway history, zero projection drift, the expected balance).
- **EAS profiles** (`apps/mobile/eas.json`): development (dev client, internal),
  preview (internal), production (auto-increment, store submit); the foundation check
  asserts all three exist.
- **Accessibility static gate** (`tools/check-accessibility.mjs`): every `Pressable`
  has an `accessibilityRole`, every `Image` has an `accessibilityLabel`; enforced in CI.
- **Release checklist and operations** (`docs/operations/release-checklist.md`): gates
  for tests, migrations, restore/outbox, privacy/security, provider acceptance,
  accessibility/performance, store/legal, rollback ownership, and digest promotion.
- **Observability**: Prometheus counters/gauges for outbox lag/DLQ, notification
  deliveries/receipts, and gateway rate limiting, plus
  `infrastructure/observability/dutch-alerts.yaml` for outbox lag, dead letters,
  delivery failures, and the rate-limited share.
- **CI**: secret scan, release-record validation, accessibility check, migration-order
  test (contiguous per-service Flyway versions), OpenTofu fmt/init/validate/plan for
  development/staging/production, and the existing backend/contract/mobile/audit jobs.
