# S2 evidence — Groups and membership

Status: all S2 acceptance paths implemented; independent re-review pending
Agent: opencode/dutch-agent
Date: 2026-11-01

## Implemented

- **Domain** (`services/ledger/src/main/java/com/dutch/ledger/group`): `Group`,
  `Membership`, roles and states with the settled invariants — at least one ACTIVE
  Admin, INVITED/PLACEHOLDER without app access, INACTIVE read-only history, and a
  removed member requiring a fresh invitation and acceptance before reactivation.
  Archive stops new work while retaining settlements and corrections.
- **Schema**: `V3__create_group_membership.sql` adds `member_group`,
  `group_membership`, and `group_membership_event`, with checks and deferred
  constraint triggers enforcing the active-Admin rule at commit.
  `V4__app_subject_member_mapping.sql` adds the app-subject authorization projection.
- **Persistence and concurrency**: `JdbcGroupRepository` and `JdbcMemberResolver`
  behind ports; `GroupRepository.save` updates only when the stored
  `aggregate_version` still matches. Mutations require `If-Match: "<version>"`; a
  mismatch is 409 `stale_version`, a malformed value is 400.
- **Membership replay**: `JdbcGroupMembershipEventConsumer` persists each event once,
  rejects a skipped version, applies it through the aggregate, and saves with the
  previous version. The unique `(group_id, aggregate_version)` row makes replay
  restart-safe.
- **Mapping feed**: `JdbcMemberMappingConsumer` applies the UMS mapping fact
  idempotently, classifies an event-id reuse race as a conflict, ignores stale mapping
  versions, and gates resolution on `ACTIVE`.
- **HTTP**: `/api/v1/groups` create/list, group read, membership invite/placeholder,
  activate, deactivate, role change, archive, and reopen, all authenticated with the
  OAuth2 resource server. Errors use `invalid_request`, `unauthorized`, `forbidden`,
  `not_found`, `stale_version`, `last_admin`, `conflict`, and `service_unavailable`
  with a correlation id. A non-member gets 404 on every group scope, including
  activation; a readable non-admin gets 403.
- **Contract**: `contracts/http/ledger/openapi.yaml` and fixtures wired into the
  validation harness, including the required `If-Match` header, a negative unknown-role
  case, and a bearer-auth check on every route.
- **Gateway**: `/api/v1/groups/**` requires authentication and forwards to the Ledger.
- **Mobile**: closed `groups-client` parsing; group list, create, and detail screens;
  invite, activate, deactivate, role change, archive, and reopen actions; loading,
  empty, retry, stale-version, and last-admin states. Admin controls are hidden for a
  non-admin member.

## Device evidence (Android)

Four flows ran on `Medium_Phone_API_36.0`:

```bash
maestro --device emulator-5554 test apps/mobile/.maestro/groups.yaml
maestro --device emulator-5554 test apps/mobile/.maestro/create-group.yaml
maestro --device emulator-5554 test apps/mobile/.maestro/group-detail.yaml
maestro --device emulator-5554 test apps/mobile/.maestro/member-view.yaml
```

They passed: group list, create group, admin invite/activate/archive/reopen, and a
non-admin member view that shows the group and its members but no invite or archive
controls. Screenshots: `android-groups.png`, `android-group-created.png`,
`android-group-detail.png`, `android-member-view.png`. The flows use the local mock API,
so they prove the client contract and states, not the live Ledger.

## Not yet implemented

- Idempotency keys for group commands; stale writes are rejected but a client retry is
  not deduplicated.
- Archived-group settlement and correction commands, which the domain permits.
- Server-side authorization on any future non-group Ledger route.
- A real IAM/UMS run; the reference adapters still do not transport onboarding events.
- Placeholder-member creation from the mobile UI (the API supports it) and UMS display
  names in the member list.

## Residual findings

- The controller tests use in-memory repository/resolver adapters; the JDBC path is
  covered by repository, mapping, and replay integration tests rather than an HTTP
  integration test.
- The membership replay and mapping consumers have no transport wiring yet; they are
  ready for the W-13 relay.
- A concurrent membership edit returns `stale_version`; the mobile refreshes and tells
  the person, but there is no merge/retry composer for the stale command.
