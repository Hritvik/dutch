# S2 evidence — Groups and membership

Status: domain, schema, HTTP, Gateway route, mobile list/create, concurrency, and mapping feed implemented; slice acceptance pending
Agent: opencode/dutch-agent
Date: 2026-11-01

## Implemented

- **Domain** (`services/ledger/src/main/java/com/dutch/ledger/group`): `Group`,
  `Membership`, roles and states with the settled invariants — at least one ACTIVE
  Admin, INVITED/PLACEHOLDER without app access, INACTIVE read-only history, archive
  retaining settlements and corrections while stopping new work, and replay-safe
  membership facts (duplicate ids are no-ops; stale versions never move backwards).
- **Schema**: `V3__create_group_membership.sql` adds `member_group`,
  `group_membership`, and `group_membership_event`, with checks and deferred
  constraint triggers enforcing the active-Admin rule at commit.
  `V4__app_subject_member_mapping.sql` adds the app-subject authorization projection.
- **Persistence**: `JdbcGroupRepository` and `JdbcMemberResolver` behind ports;
  `GroupService` applies the non-enumeration rules (404 for an unreadable scope, 403
  for a readable scope without the role).
- **Concurrency**: `GroupRepository.save` updates only when the stored
  `aggregate_version` still matches the version the command loaded; a stale writer gets
  a 409 `conflict` and cannot overwrite another membership edit.
- **Mapping feed**: `JdbcMemberMappingConsumer` applies the UMS mapping fact
  idempotently, rejects event-id reuse with a different payload, ignores stale mapping
  versions, and gates resolution on `ACTIVE`.
- **HTTP**: `/api/v1/groups` create/list, group read, membership invite/placeholder,
  activate, deactivate, role change, archive, and reopen, all authenticated with the
  OAuth2 resource server. Errors use `invalid_request`, `unauthorized`, `forbidden`,
  `not_found`, `conflict`, and `service_unavailable` with a correlation id.
- **Contract**: `contracts/http/ledger/openapi.yaml` and fixtures wired into the
  validation harness, including a negative unknown-role case and a bearer-auth check
  on every route.
- **Gateway**: `/api/v1/groups/**` requires authentication and forwards to the Ledger.
- **Mobile**: closed `groups-client` parsing, a group list with loading, empty, and
  retry states, and a create-group form that posts the pinned request and returns to
  the refreshed list.

## Device evidence (Android)


They passed: signed-out render, test identity, authenticated shell, "View groups",
the list with `Flat 12`, the create form, entering `Goa trip`, creating the group, and
the refreshed list containing it. Screenshots: `android-groups.png`,
`android-group-created.png`. The flows run against the local mock API, so they prove
the client contract and states, not the live Ledger.

## Not yet implemented

- The mobile group-detail and membership-management flows; the list and create form are
  the current UI.
- Explicit client preconditions (`If-Match`) and idempotency keys. Stale writers are
  already rejected at save, but a client cannot state the version it edited.
- Server-side authorization on any future non-group Ledger route.
- A real IAM/UMS run; the reference adapters still do not transport onboarding events.
- Archived-group settlements and corrections, which the domain already permits.

## Residual findings

- The controller tests use in-memory repository/resolver adapters; the JDBC path is
  covered by repository and mapping integration tests rather than an HTTP integration
  test.
- The mapping consumer has no transport wiring yet; it is ready for the W-13 relay.
- Concurrent membership edits are rejected, but there is no retry loop or merge UI.
