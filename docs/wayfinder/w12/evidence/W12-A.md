# Evidence — W12-A serve profile state and the profile split

Repository: `~/repositories/dutch`
Commit: `540c737`
Status: green, awaiting review

## Delivered

- `GET /api/v1/me/profile-state` returns `{data:{state}}` with only `PROFILE_REQUIRED`,
  `PROFILE_PROVISIONING`, or `PROFILE_READY`. A subject with no Dutch profile is
  `PROFILE_REQUIRED`, not an error.
- `GET /api/v1/me` keeps the split: `409 profile_required` until the profile is ready and
  the Member lifecycle is active, then only the Dutch-owned fields.
- Neither response exposes the app subject, a global identity, a member identifier it does
  not own, credentials, or tokens.

## Verification

`./gradlew :services:ums:test --tests '*ProfileStateControllerTest'` and the full
`:services:ums:test` suite pass. Tests cover unknown, provisioning, and ready subjects, the
correlation header echo, the unauthenticated rejection, the 409 split, and the absence of
identity fields.

## Limits

- `retryAfterSeconds` is omitted: Dutch has no authoritative provisioning ETA to publish,
  and inventing one would be a false promise.
- No consumer/contract or IAM repository changes were made.
