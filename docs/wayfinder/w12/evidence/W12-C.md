# Evidence — W12-C prove the profile journey end to end

Repository: `~/repositories/dutch`
Status: green, awaiting review

## Delivered

`ProfileJourneyIntegrationTest` drives the real controller, security chain, correlation filter,
consumer, and PostgreSQL:

- **Required before consumption:** an unconsumed subject answers 409 `profile_required` with the
  pinned message/correlation from `/api/v1/me`, and `PROFILE_REQUIRED` from `/profile-state`.
- **Provisioning:** after the onboarding fact is consumed and the Dutch product advances the
  record, `/profile-state` reports `PROFILE_PROVISIONING`.
- **Ready:** completing the Dutch-owned record flips both endpoints — 200 with only
  `memberId`, `displayName`, `profileState`, `lifecycleState`.
- **Not ready:** a suspended Member is `PROFILE_REQUIRED` on `/profile-state` and 409 on `/me`.
- **Correlation:** a non-conforming inbound value is regenerated in the pinned shape and echoed
  even on the rejection path.
- **Privacy:** the ready body contains no app subject, `aps_` reference, identity, token,
  credential, password, or email.

## Verification

`./gradlew :services:ums:test --rerun-tasks --no-daemon` with the local Docker context:

## Limits

- This is the local reference-adapter journey; it does not exercise a live IAM issuer, the UMS
  HTTP surface, or the Dutch mobile client.
- The transition to `PROFILE_READY` is simulated with the Dutch-owned completion write, because
  UMS readiness is consumed rather than authored here.

## Review remediation

- **Lifecycle negatives were nominal.** The suspended case started from `PROFILE_REQUIRED`, so the
  lifecycle gate could be deleted and the test still passed. It now completes the profile first,
  then exercises both `SUSPENDED` and `DEPARTED`, asserting `PROFILE_REQUIRED` and 409 each time.
- **Auth bypassed the resource server.** Requests used a security post-processor; they now send a
  real `Authorization: Bearer` header through the actual filter chain, and a new test proves a
  missing bearer token returns the pinned `unauthorized` envelope.
- **Tautology pressure reduced.** The ready response now asserts the closed four-key set, the
  `mem_` identifier pattern, and case-insensitive absence of personal data on the ready, 409, and
  state bodies. State writes remain the Dutch-owned completion signal; that is the honest scope.
- Correlation replacement now asserts the echoed value differs from the invalid input and appears
  in the 409 body.
- The lifecycle update carries a `WHERE`, so parallel execution cannot corrupt the suite.
