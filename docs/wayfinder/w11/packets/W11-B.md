# W11-B — Consume onboarding idempotently

## Objective

Consume `iam.app-subject.onboarding-ready.v1` in one transaction, creating exactly one Member Profile, mapping and Dutch mapping event per `(appRegistrationId, appSubject)`.

## Outputs and ownership

Own the consumer, event record, mapping record and their unit/integration tests. Do not change the profile HTTP controller.

## Acceptance

- Duplicate delivery of the same event is a no-op returning the existing mapping.
- A different event id for the same subject and payload returns the existing mapping with no second profile or event.
- Same event id with a different payload fails closed without state change.
- One inbox row per event identity (producer + event id), one profile and one outbox event per `(appRegistrationId, appSubject)`.
- The outbox payload is exactly `appRegistrationId, appSubject, memberId, mappingVersion, profileState, lifecycleState` inside the pinned envelope and contains no identity/identifier/token.
- UMS never reads IAM persistence.
- The `@Transactional` boundary is proven by the W11-C Spring-context rollback test.

```bash
./gradlew :services:ums:test --tests '*MemberProfileConsumer*'
```
