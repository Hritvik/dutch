# W11-A — Reshape the UMS schema for app-scoped onboarding

## Objective

Replace the legacy identity-keyed member tables with app-scoped member profiles, a producer-keyed inbox with payload fingerprints, a checkpoint and a contract-shaped outbox.

## Outputs and ownership

Own `services/ums/src/main/resources/db/migration/**` and the persistence records/repositories. Do not change the consumer or HTTP surfaces.

## Acceptance

- `member_profile` is keyed by `member_id` (`mem_`), unique on `(app_registration_id, app_subject)`, with `profile_state` and `lifecycle_state` from the pinned contract vocabularies.
- `inbox_event` is keyed by `(producer, event_id)` and stores a canonical payload fingerprint.
- `outbox_event` stores text `evt_` ids and the IAM envelope columns.
- A forward-only V3 migration leaves no legacy `identity_id`/UUID member columns.
- Migration tests run clean. **Scope amendment (recorded):** V3 intentionally discards the prototype tables because there is no live UMS population; the upgrade test proves the discard and the resulting app-scoped schema.

## Verification

```bash
./gradlew :services:ums:test --tests '*Migration*'
```
